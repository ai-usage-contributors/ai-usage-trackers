1. HOW TO READ THIS RECORD

Given/When/Then describes the scenario and expected outcome. Observed records
what evidence actually establishes; it must never be replaced with an expectation.
Execution is separate from documentation. Sections 2-5 preserve historical/planned records; section 7 contains agent-run R1 results and section 8 records owner-reported installed-plugin testing.

Stable IDs W/S/T/A/Q/C retain the historical coverage IDs. N01-N08 expand scope
for current changes. Record each environment/input/failure variant separately.
A broad parent passes only when all required variants pass. Use PASS, LIMITED,
INCONCLUSIVE, FAIL, BLOCKED or NOT RUN, with a specific reason/evidence.
UNTESTED below is the original H1 status and corresponds to NOT RUN.
Evidence tier USER-PASS records owner-reported successful use of the installed
plugin in the IDE. It is distinct from agent-observed PASS and automated checks.
Record scope, date and known installation details; unknown hashes/builds remain
unknown. It does not convert unexecuted agent checks into executions, certify
unobserved instrumentation, or carry automatically to a rebuilt artifact.

Each executed case must resolve to a run containing:
- Plugin version AND exact artifact SHA256; source revision or identified local
  snapshot. Same version number alone never establishes the same candidate.
- Execution date/start/end, tester, IDE version/build, OS, theme, IDE zoom,
  OS display scaling, window size, input method and screen reader/version.
- Fixture/config IDs, known totals, relevant zone/reset reference, initial
  settings and expected persistence behavior.
- Observed outcome, status, evidence paths/time intervals, defects, restoration
  outcome and linked retest records. Keep local evidence under agent-logs;
  only sanitized summaries belong in version control.
